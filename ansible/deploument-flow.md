# Deployment Flow

This diagram shows what Ansible does when you run the deployment.

```
┌─────────────────────────────────────────────────────────────────┐
│                    ANSIBLE DEPLOYMENT FLOW                       │
└─────────────────────────────────────────────────────────────────┘

1. PREPARE SERVER
   ┌──────────────────────────────────────────┐
   │ • Install Docker & Docker Compose        │
   │ • Add jenkins user to docker group       │
   │ • Setup directories                      │
   └──────────────────────────────────────────┘
                    ↓

2. CLONE YOUR REPOSITORY
   ┌──────────────────────────────────────────┐
   │ Git Clone → /opt/stock-pos               │
   │                                          │
   │ Your repo already has:                   │
   │ ✅ Dockerfile                            │
   │ ✅ docker/nginx/nginx.conf               │
   │ ✅ docker/nginx/conf.d/default.conf      │
   └──────────────────────────────────────────┘
                    ↓

3. GENERATE REQUIRED FILES
   ┌──────────────────────────────────────────┐
   │ Generate ONLY these 3 files:             │
   │                                          │
   │ ✅ .env                                  │
   │    (from .env.j2 template)                │
   │    → DB passwords, ports, config         │
   │                                          │
   │ ✅ docker-compose.yml                    │
   │    (from docker-compose.yml.j2)          │
   │    → PostgreSQL, Redis, MinIO, Nginx     │
   │                                          │
   │ ✅ docker-compose.prod.yml               │
   │    (from docker-compose.prod.yml.j2)     │
   │    → Express app service definition      │
   │                                          │
   │ SKIP these (use your files):             │
   │ ❌ Dockerfile (uses yours)               │
   │ ❌ nginx.conf (uses yours)               │
   │ ❌ default.conf (uses yours)             │
   └──────────────────────────────────────────┘
                    ↓

4. BUILD DOCKER IMAGE
   ┌──────────────────────────────────────────┐
   │ docker build -t stock-pos-app:latest .   │
   │                                          │
   │ Uses YOUR Dockerfile from repo           │
   └──────────────────────────────────────────┘
                    ↓

5. DEPLOY WITH DOCKER COMPOSE
   ┌──────────────────────────────────────────┐
   │ docker compose -f docker-compose.yml \   │
   │                -f docker-compose.prod.yml │
   │                up -d                      │
   │                                          │
   │ Starts all containers:                   │
   │ • PostgreSQL (port 5433)                 │
   │ • Redis (port 6380)                      │
   │ • MinIO (ports 9000, 9001)               │
   │ • Express App (port 3000)                │
   │ • Nginx (ports 8081, 8443)               │
   └──────────────────────────────────────────┘
                    ↓

6. VERIFY DEPLOYMENT
   ┌──────────────────────────────────────────┐
   │ • Wait for containers to be healthy      │
   │ • Check health endpoint                  │
   │ • Display container status               │
   │ • Show logs                              │
   └──────────────────────────────────────────┘
                    ↓
              
         ✅ DEPLOYMENT COMPLETE!
```

## File Sources Summary

```
/opt/stock-pos/
├── .env                              ← Generated by Ansible from .env.j2
├── docker-compose.yml                ← Generated by Ansible from docker-compose.yml.j2
├── docker-compose.prod.yml           ← Generated by Ansible from docker-compose.prod.yml.j2
├── Dockerfile                        ← From YOUR repo (Ansible doesn't touch it)
├── package.json                      ← From YOUR repo
├── index.js (or your app files)      ← From YOUR repo
└── docker/
    └── nginx/
        ├── nginx.conf                ← From YOUR repo (Ansible doesn't touch it)
        └── conf.d/
            └── default.conf          ← From YOUR repo (Ansible doesn't touch it)
```

## What Ansible Does vs What You Provide

### Ansible Generates (3 files):
1. ✅ `.env` - Environment variables
2. ✅ `docker-compose.yml` - Base infrastructure services
3. ✅ `docker-compose.prod.yml` - App service definition

### You Provide (from your Git repo):
1. ✅ `Dockerfile` - How to build your app
2. ✅ `docker/nginx/nginx.conf` - Nginx config
3. ✅ `docker/nginx/conf.d/default.conf` - Nginx server config
4. ✅ All your application code

## Why This Approach?

**Ansible generates only what needs to be dynamic:**
- Environment variables (passwords, ports) change per environment
- Docker Compose files need to use inventory variables

**You control application-specific configs:**
- Your Dockerfile defines how your app builds
- Your nginx configs define how your app is served
- No templates overwrite your carefully crafted configurations

This gives you full control while automating the deployment process!
